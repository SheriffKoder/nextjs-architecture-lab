# URL kit chrome transport migration

Phase 2.6 implementation notes for the hybrid page.

## What changed

Remaining url-kit chrome that read or wrote URL via Next.js navigation now uses **`url-params`** transport — same hooks and components as RSC, shallow commit on hybrid.

### Read-path migrations (`useEffectiveSearchParams`)

| Component | Change |
|-----------|--------|
| `PillFilter/pill-search-bar` | `q` sync from transport |
| `expandable-search/expandable-search-control` | `q` sync from transport |
| `dropdown-filter/components/search-bar` | `q` sync from transport |
| `dropdown-filter/dropdown-filter.tsx` | Active selections, range sync via `effectiveParams` + `committedSnapshot` deps |

Removed duplicate `expandable-search-control.tsx` at components root — barrel exports canonical subfolder only.

### Write-path / hook migrations (`useUrlParamsTransport`)

| Area | Change |
|------|--------|
| `feature-sorting-builder-control/` | Imports canonical `useUrlSorting` |
| `feature-query-builder-filter/hooks/use-url-query-filter` | `filter=` blob via `buildParams` + `commit` |
| `ai-filter/components/nl-filter-assistant` | Bulk NL patches via transport |
| `ai-filter/hooks/use-apply-text-search-from-nl-assistant` | Text search apply/clear via transport |

## RSC vs hybrid

| Mode | Transport | Chrome imports |
|------|-----------|----------------|
| RSC (`/demo-rsc-page`) | Router fallback (no provider) | `@/platform/url-kit/*` |
| Hybrid (`/demo-hybrid-page`) | `<ShallowUrlProvider>` | Same imports |

No duplicate chrome forks. Router fallback behavior on RSC is unchanged.

## Verify shallow vs router mode

1. **Hybrid:** Change a pill/dropdown search or filter on `/demo-hybrid-page` — URL updates without full document navigation; TanStack list refetches; input/badge state stays in sync.
2. **RSC:** Same controls on `/demo-rsc-page` — soft navigation + Suspense islands behave as before.
3. **NL assistant:** Apply/clear on hybrid — no RSC flight; list refetches from updated snapshot.
